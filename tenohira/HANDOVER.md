## 1. これは何か

岡田式浄化療法の施術の様子をスマホやパソコンのカメラで映し、**施術者の掌がどの方向を向いているか**を推定して、**受ける方の体のどの範囲に、何秒向いていたか**を自動で記録する試作です。

浄化療法では、掌に垂直な方向に光（エネルギー）が出るという前提に立っています。このプログラムは、その前提どおり「掌に垂直な方向」を矢印として計算し、矢印の先が体のどの範囲に当たっているかを判定します。

### 作った理由

- 今の浄化療法記録アプリでは、人体図に赤・青の色を塗って部位を記録するが、**高齢の方には操作が難しい**という声が出ている。
- 手書きの記録票は人によって書き方がまちまちで、データとして集めにくい。
- そこで、**撮影するだけで「どこに何分」が記録される**仕組みを目指す。入力の手間をなくし、記録の正確さと再現性を上げる。

### 将来の位置づけ

浄化療法の結果を事実として集積し、統合医療の社会モデルづくり（自治体との協働など）に使う。施術記録アプリ本体に組み込み、部位と時間を自動で入力する部品になる想定。

## 3. 技術構成

- 1枚のHTML。ビルド不要。
- 画像認識：Google の **MediaPipe Tasks Vision 0.10.14**（jsDelivr から ESM で読み込み）
  - `https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.14/vision_bundle.mjs`
  - wasm：`https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.14/wasm`
  - 手のモデル：`https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task`
  - 骨格のモデル：`https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_lite/float16/1/pose_landmarker_lite.task`
- `HandLandmarker`（手21点、最大2本）と `PoseLandmarker`（骨格33点、最大2人）を `runningMode: "VIDEO"` で毎フレーム実行。
- GPU で作成し、失敗したら CPU で作り直す。
- フォント：BIZ UDPGothic / BIZ UDGothic（Google Fonts）。**和文は日本語字形のフォントを使うこと（中国語字形のフォントは使わない）。**

## 4. 処理の流れ

```
カメラ映像または動画ファイル
  → 手の21点・骨格33点を推定（MediaPipe）
  → 受ける方を選ぶ（chooseRecipient）
  → 受ける方の向きを判定（bodyView：前面／背面／側面）
  → 骨格から部位の範囲（円）を作る（buildZones）
  → 手ごとに掌の中心と、掌に垂直な向きを計算（palmFrame）
  → 向きの延長線が最初に当たる範囲を探す（hitZone）
  → 0.25秒以上同じ範囲なら確定し、時間を加算（updateTracks）
  → 画面に描画、部位ごとの合計時間を表示、CSVに書き出し
```

座標はすべて画素単位に変換して計算しています（`x*幅, y*高さ, z*幅`）。

## 5. 計算の中身

### 5.1 掌に垂直な向き（palmFrame）

- 手首 `0`、人差し指の付け根 `5`、中指の付け根 `9`、小指の付け根 `17` を使う。
- 向き `n = normalize( cross(p5 − p0, p17 − p0) ) × mult`
- 掌の中心 `c` は 0・5・9・17 の平均。
- `mult`（+1 / −1）は左右の手で外積の向きが逆になることの補正。

### 5.2 左右の手の補正と「掌の向きを合わせる」

- MediaPipe の左右ラベルは**映像が左右反転している（自撮り）前提**で付くため、反転していない映像では実際の左右と逆になる。
- 初期値：`{ Left: +1, Right: −1 }`（反転していない映像を想定）。
- 「掌の向きを合わせる」ボタン：2秒間、掌をカメラに向けてもらい、補正前の向きの z の平均が負（カメラ方向）になるよう `mult` を決める。結果は `localStorage` の `tenohira-calib` に保存。

### 5.3 受ける方の向き（bodyView）

- 肩幅 < 胴の長さ × 0.38 → 側面
- 鼻の見え具合（visibility）< 0.35 → 背面
- 人の左肩（11）が画面の右側にある → 前面、左側にある → 背面
- 画面の「受ける方の向き」で手動指定も可能。

### 5.4 部位の範囲（buildZones）

骨格の肩（11・12）と腰（23・24）から、肩幅と胴の長さで基準の大きさ `u = max(肩幅, 胴の長さ×0.55)` を決め、各部位を円で置いています。

| 共通 | 背面・側面のとき | 前面のとき |
|---|---|---|
| 頭部／後頭部、首（左・右）、肩（左・右）、肘（左・右）、膝（左・右、見えている時だけ） | 肩甲骨（左・右）、背中中央、腎臓（左・右）、腰（左・右） | 胸、みぞおち、腹部 |

- 部位名の左右は**受ける方本人の左右**。
- **首（左・右）は `caution: true`。** 掌が首に向くと「首まわり：安全に注意してください」と表示する。

### 5.5 当たり判定（hitZone）

- 掌の向きを画面上の方向に直した長さが 0.3 未満（掌がカメラの手前か奥を向いている）→ 掌の中心が重なっている範囲で判定（`mode: "depth"`）。
- それ以外 → 掌の中心から向きに沿って `0.1u` から `3u` まで `u/24` 刻みで進み、最初に入った範囲（円の中心に最も近いもの）を採用（`mode: "ray"`）。

### 5.6 受ける方の選び方（chooseRecipient）

- 自動：手首の位置が骨格の手首（15・16）と画面幅の7%以内で一致する人を施術者とみなし、それ以外で胴が一番大きい人を受ける方にする。
- 自分自身（自己施術）、画面の左の人、画面の右の人も選べる。

### 5.7 記録

- 手ごとに、同じ範囲が 0.25 秒続いたら確定（ちらつき防止）。
- 両手が同じ範囲を向いていても、時間は1回分だけ加算。
- 1フレームの経過時間は最大 0.25 秒に制限（処理落ち対策）。
- 区間（開始秒・終了秒・手・部位）も記録。手の名前は `Left` ラベル → 手A、`Right` → 手B。
- CSV：先頭に BOM を付け、Excel で文字化けしない形にしている。

```
部位,合計秒
腎臓（右）,42.3
...

開始秒,終了秒,手,部位
3.2,45.5,手A,腎臓（右）
...
```

## 6. 動作環境と制約

- **カメラは安全な環境でしか使えない。** スマホは `https://` のページ（GitHub Pages など）で開く必要がある。パソコンは保存したファイルを Chrome で直接開けば動く想定。
- **Claude の画面の中（プレビューやアーティファクト）では、カメラ・CDNからのデータ読み込み・ファイル保存が使えない。** 依頼者が最初に試したときカメラが開けなかったのは、おそらくこのため。v0.2 で、開き方に問題があるとき・カメラの許可がないとき・データが読み込めないときに、理由を画面に表示するようにした。
- 初回に認識用のデータ（数MB）をインターネットから読み込む。
- **映像は保存も送信もしない。** 端末の中だけで処理する。これは個人情報の扱い上の前提なので、今後も守ること。

## 7. 確認済みのこと・未確認のこと

**確認済み**
- 位置計算（GEOMETRY ブロック）を、人工的な骨格と手の座標でテスト。背面・前面の判定、範囲の作成、掌の向きの延長線と重なり位置の両方での判定、向きを反転したときに外れることを確認（7件合格）。
- スクリプト全体の構文チェック。

**未確認**
- 実際のカメラ映像での動作（範囲の位置のずれ、判定の安定性、処理速度）。
- スマホ（iPhone / Android）での動作。
- 前面カメラ（左右反転の扱い）。

## 8. 次にやること（優先順）

1. **GitHub Pages に置き、実機で動かす。**
   例：浄化療法アプリのリポジトリ `testmoahiroshima/zyoukaryouhouapurisaisinn` の中に `tenohira/index.html` として置き、Pages の URL で開く。依頼者とスマホ・パソコンで動作を確認する。
2. **範囲を 3級テキストの 19 か所の急所に合わせて置き直す。**
   - 3級テキストでは探査できる急所が19か所定義されている（番号①〜⑲）。
   - 既存の記録アプリでの決定事項：⑧は背面の両脇に置く。側面図は頭と首だけ。**⑥⑦⑩⑪（首まわり）は自動で安全注意を出す。**
   - 優先度：**腎臓が第一、肩甲骨が第二**。画面上の強調もこの順に。
   - 急所の正確な位置は 3級テキストを依頼者に確認すること（推測で置かない）。
3. **ランドマークの揺れを抑える**（One Euro Filter などで平滑化）。判定が飛ぶ場合の対策。
4. **前面カメラ（自撮り）で左右反転された映像の扱い**を確認し、必要なら表示だけ反転して計算は反転しない形に整理。
5. **認識用データ（wasm と .task）をリポジトリ内に置く**ことを検討。外部サイトに依存せず、読み込みも安定する。
6. **浄化療法記録アプリ本体への組み込み**
   - 施術記録の「部位・時間」欄に自動で入る形にする。
   - サーバーに送るのは「どの部位に何秒」という結果だけ。映像は送らない。
   - 同意画面に「カメラで施術の様子を認識すること（映像は保存しない）」の項目を加える。
7. 将来の拡張候補：サーモグラフィー画像（InfiRay P2 Pro などの温度データ付き画像）や筋硬度計の値を、同じ施術記録に施術前後で並べて保存する。

## 9. 守ってほしい方針

- **高齢の方でも使えること**を最優先に。ボタンは大きく、言葉は平易に。専門用語や英語を画面に出さない。
- **映像は保存・送信しない。** 結果だけを扱う。
- **首まわりの安全注意**を外さない。
- 和文フォントは**日本語字形**のもの（BIZ UDPGothic など）を使う。
- 変更したら `tenohira-geometry.test.mjs` を実行し、合格を確認する。計算を変えた場合はテストも更新する。
